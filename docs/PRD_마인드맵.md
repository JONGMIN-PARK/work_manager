## 1. 배경

지금 앱은 **이미 정해진 구조**(프로젝트 → 마일스톤 → 체크리스트, 이슈, 수주대장)를 기록하는 데 강하다.
그런데 그 구조가 만들어지기 **전 단계**와, 흩어진 데이터를 **한 장으로 보는 단계**가 비어 있다.

| 문제 | 현상 |
|------|------|
| **착수 전 구상이 앱 밖에 있음** | 신규 프로젝트 WBS·업무 분장을 화이트보드·엑셀·종이로 그리고, 앱에는 결과만 다시 입력 |
| **팀원별 부하가 한눈에 안 보임** | 누가 어떤 프로젝트·마일스톤·이슈·A/S를 들고 있는지 탭을 돌아다녀야 파악 |
| **개인 업무 정리 공간 없음** | 내가 맡은 일 + 아직 등록 안 된 할 일·아이디어를 같이 정리할 곳이 없음 |
| **회의 결론 → 작업 전환 단절** | 회의·사전검토에서 나온 아이디어를 실제 마일스톤·이슈로 옮기는 과정이 수작업 |

### 목표

| 목표 | 측정 |
|------|------|
| 구상 단계를 앱 안으로 | 생성된 맵 수 · 맵에서 승격(→마일스톤/이슈)된 노드 수 |
| 데이터 한 장 보기 | 자동 생성 맵(프로젝트·팀원·개인) 조회 수 |
| 개인 업무 정리 | 개인 맵 보유 사용자 비율 · 주간 재방문율 |

### 설계 원칙

- **XMind 수준의 편집 경험** — 구조(마인드맵·논리도·조직도·피시본·타임라인), 관계선·경계·요약, 마커·라벨, 작업 정보, 프레젠테이션 모드까지 XMind의 검증된 기능 체계를 따른다(3.0 대응표).
- **일반 마인드맵 + "살아있는 노드"** — 자유 텍스트 노드에 더해, 앱의 실제 데이터(프로젝트·마일스톤·이슈·팀원·요소기술…)를 **참조**하는 노드를 둔다. 참조 노드는 진척률·상태·담당자를 원본에서 실시간으로 보여준다. 이것이 외부 마인드맵 툴과의 차별점.
- **원본은 하나** — 참조 노드는 데이터를 복사하지 않고 `link_type + link_id`만 저장. 원본이 삭제되면 "끊긴 링크"로 표시.
- **기존 규약 준수** — 멀티테넌트(`tenant_id`), 낙관적 락(`version`), 편집 잠금(`edit_locks`/`locks.js`), 소프트 삭제(`deleted_at`), 모달은 `wmGuardedModal`, 변경 알림은 `wmDataBus`, 서버 전용 모드(camelCase↔snake_case 매핑).
- **빌드 없음** — 현재 프론트 구조(전역 스크립트 + `setMode`)에 맞춰 단일 모듈 `mindmap.js`로 구현.

## 2. 맵의 종류 (범위 · 공개)

| 종류 | 소유 | 공개 범위 | 대표 용도 |
|------|------|-----------|-----------|
| **개인** | 본인 | 본인만 (공유 시 지정 사용자 읽기) | 내 업무 정리, 할 일·아이디어 |
| **프로젝트** | 프로젝트에 귀속 | 프로젝트 접근 권한 그대로 (`lib/project-access.js`) | WBS 구상, 기술 검토, 리스크 정리 |
| **팀(부서)** | 부서 | 부서원 (`department_id` 스코프, 008) | 업무 분장, 팀 목표, 역량 지도 |
| **조직** | 작성자 | 테넌트 전체 읽기 | 사업 구조, 요소기술 지도 |

- 편집 권한: 소유자 + 편집자 목록(`editors`). 프로젝트 맵은 프로젝트 편집 권한(v13.213)을 따름.

### 2.1 기능 사용 권한 (결정)

**관리자(admin)만 기본 사용, 그 외 사용자는 관리자가 지정했을 때만 사용 가능.**

- 판정: `role === 'admin'` 또는 `user_settings` key `mindmap_access` = `{ enabled: true }`
  → 운영자 모드(`middleware/operator.js`, `PUT /api/users/:id/operator-mode`)와 **같은 패턴**으로 구현
- 서버: `middleware/mindmap-access.js`의 `requireMindmapAccess`를 `/api/mindmaps/*` 전체에 적용 (403)
- 로그인 응답(`auth.js`)에 `mindmapAccess` 플래그 포함 → 플래그가 없으면 상위 탭 자체를 숨김(`tabUserAdmin`처럼 `display:none`)
- 관리 UI: 마인드맵 목록 화면의 **[👥 사용 권한]** 모달에서 사용자별 켜기/끄기 (`GET/PUT /api/mindmaps/access/users`, admin only, 감사 로그) — 구현 시 사용자 관리 페이지 대신 기능 화면 안에 둠
- 권한 회수 시: 그 사용자가 만든 맵은 삭제하지 않고 보존, 접근만 차단 (관리자는 계속 열람·소유자 이관 가능)
- 권한이 있어도 맵 단위 공개 범위(위 표)는 그대로 적용. 권한이 없는 사용자는 공유·편집자 대상으로 지정 불가

### 3.2 살아있는 노드 — 데이터 참조 (Phase 1 일부 · Phase 2)

노드 추가 시 "앱 데이터 연결"로 검색·선택. 노드 카드에 원본 상태를 배지로 표시, 클릭 시 해당 상세 화면으로 이동.

| ref.type | 원본 | 노드에 표시 |
|-----------|------|-------------|
| `project` | projects | 단계·진척률·PM |
| `milestone` | milestones | 기간·진척률·담당자 |
| `issue` | issues | 상태·우선순위·담당자 |
| `user` | users | 이름·부서·현재 담당 건수 |
| `tech` | tech_assets | TRL·상태 |
| `prestudy` | prestudies | 단계·결론 |
| `as` | as_tickets | 상태·접수일 |
| `meeting` | meetings | 일자·제목 |

- 상태는 맵을 열 때 `/api/mindmaps/resolve` 로 한 번에 불러오고, 툴바 [↻ 상태]로 다시 불러옴 (12장)
- 원본 접근 권한이 없는 사용자에게는 "🔒 비공개 항목"으로 표시 (데이터 노출 금지)

### 3.3 자동 생성 템플릿 (Phase 2)

빈 맵 대신 앱 데이터로 **초안을 자동 생성** → 사용자가 자유 노드를 덧붙여 다듬음.

| 템플릿 | 구조 |
|--------|------|
| **프로젝트 구조도** | 프로젝트 → 마일스톤 → 체크리스트 / 개발 아이템 / 미해결 이슈 |
| **팀원 업무 지도** | 부서 → 팀원 → 담당 프로젝트·마일스톤·이슈·A/S (건수·지연 강조) |
| **내 업무** | 나 → 진행 중 마일스톤 / 내 이슈 / 내 A/S / 이번 주 업무보고 항목 + 자유 "할 일" 가지 |
| **빈 템플릿** | 회의·브레인스토밍·SWOT·5Why 등 고정 골격 |

- 자동 생성 노드는 참조 노드이므로 이후에도 상태가 살아있음
- "다시 동기화" 버튼: 원본에 새로 생긴 항목을 추가 노드로 제안(자동 삽입 X, 사용자 확인)

### 3.4 노드 승격 — 구상 → 실제 작업 (Phase 2)

자유 노드를 우클릭 → **"마일스톤으로 만들기 / 이슈로 만들기 / 체크리스트로 만들기"**.
- 기존 생성 폼(모달, `wmGuardedModal`)을 노드 텍스트·담당자·마감일이 채워진 상태로 열기
- 생성 성공 시 해당 노드가 참조 노드로 전환
- 하위 노드 일괄 승격: "마일스톤 A 아래 자식들을 체크리스트로" 같은 일괄 변환

### 3.5 AI 기능 (결정: 포함)

기존 `services/ai-claude.service.js`의 `callJson`을 재사용합니다. 월 사용량은 `ai_query_usage`(029)에 같은 방식으로 기록하고 할당량을 적용합니다. AI 결과는 **바로 반영하지 않고 미리보기(점선 노드)로 보여준 뒤, 사용자가 채택하거나 버립니다**.

| 기능 | 입력 | 출력 | Phase |
|------|------|------|-------|
| **아이디어 확장** | 선택 노드 + 상위 경로 | 하위 노드 후보 3~7개 | 2 |
| **텍스트 → 맵 생성** | 자유 텍스트(회의 메모·요구사항·메일 붙여넣기) | 구조화된 트리 | 2 |
| **WBS 초안 생성** | 프로젝트 개요(수주대장·사양표·사전검토 내용) | 단계 → 작업 → 산출물 트리 + 작업 정보(기간 추정) | 2 |
| **요약 · 정리** | 가지 또는 맵 전체 | 요약(Summary) 노드 / 중복·유사 노드 병합 제안 | 2 |
| **리스크 · 누락 점검** | 프로젝트 맵 + 참조 노드 상태 | 검토 안 된 영역, 지연 위험 가지 하이라이트 | 3 |
| **승격 보조** | 선택 가지 | 마일스톤/이슈/체크리스트 매핑 제안 → 승격 폼에 채워서 열기 | 3 |
| **맵 → 보고서 문장** | 맵 | 주간업무보고·회의록용 개조식 텍스트 | 3 |

- API: `POST /api/mindmaps/ai` `{ action, mapId, nodeId?, text? }` → `{ nodes: [...] }` (5.3 노드 형식, JSON 스키마 검증 후 반환)
- 프롬프트에는 **요청자가 접근 가능한 항목만** 넣음 (참조 노드도 권한 필터 후 직렬화)
- AI 미설정(`isReady()` false) 시 버튼 숨김
- 진입: 노드 우클릭 메뉴, 툴바 `✨ AI` 드롭다운

## 4. 화면 구성

## 5. 데이터 모델

### 5.1 저장 방식 결정

| 안 | 장점 | 단점 |
|----|------|------|
| **A. 맵 1행 + 노드 JSONB 문서** | 저장·불러오기 1회, 되돌리기/버전 스냅샷 쉬움, 구현 단순 | 동시 편집 불가(잠금 필요), 노드 단위 검색은 GIN 인덱스 |
| B. 노드별 행 | 노드 단위 갱신·동시 편집 기반 | 저장 API 복잡, 순서·이동 트랜잭션 비용, 수백 노드 로드 쿼리 |

**권장: A안.** 이 앱의 편집 모델은 이미 "편집 잠금 + 낙관적 락"이고, 마인드맵은 노드 수백 개 수준이라 문서 단위가 맞다. 실시간 공동 편집은 범위 밖(10장).
역참조("이 이슈가 어떤 맵에 있나")는 별도 경량 테이블 `mindmap_links`로 해결.

### 5.2 `056_mindmaps.sql`

```sql
CREATE TABLE IF NOT EXISTS mindmaps (
  id            VARCHAR(100) PRIMARY KEY,
  tenant_id     UUID NOT NULL DEFAULT '00000000-0000-0000-0000-000000000001' REFERENCES tenants(id),
  title         VARCHAR(255) NOT NULL,
  scope         VARCHAR(20) NOT NULL DEFAULT 'personal',   -- personal | project | dept | org
  owner_id      UUID REFERENCES users(id),
  project_id    VARCHAR(100),                              -- scope=project
  department_id UUID,                                      -- scope=dept
  editors       JSONB DEFAULT '[]',                        -- 추가 편집자 user id
  viewers       JSONB DEFAULT '[]',                        -- personal 공유 대상
  theme         VARCHAR(20) DEFAULT 'default',
  template      VARCHAR(30),                               -- 생성 템플릿(통계용)
  doc           JSONB NOT NULL DEFAULT '{}',               -- { sheets: [{ id, title, structure, root, floating: [], relations: [] }] }
  node_count    INT DEFAULT 0,
  thumbnail     TEXT,                                      -- 목록용 저해상도 data URL (선택)
  pinned_by     JSONB DEFAULT '[]',                        -- 즐겨찾기 user id
  deleted_at    TIMESTAMPTZ,
  deleted_by    UUID REFERENCES users(id),
  version       INT NOT NULL DEFAULT 1,
  created_by    UUID REFERENCES users(id),
  updated_by    UUID REFERENCES users(id),
  created_at    TIMESTAMPTZ DEFAULT now(),
  updated_at    TIMESTAMPTZ DEFAULT now()
);

CREATE INDEX IF NOT EXISTS idx_mindmaps_owner   ON mindmaps (tenant_id, owner_id, updated_at DESC) WHERE deleted_at IS NULL;

CREATE INDEX IF NOT EXISTS idx_mindmaps_project ON mindmaps (tenant_id, project_id) WHERE deleted_at IS NULL;

CREATE INDEX IF NOT EXISTS idx_mindmaps_dept    ON mindmaps (tenant_id, department_id) WHERE deleted_at IS NULL;

-- 참조 노드 역인덱스 — 저장 시 doc에서 재계산(삭제 후 삽입)
CREATE TABLE IF NOT EXISTS mindmap_links (
  map_id     VARCHAR(100) NOT NULL REFERENCES mindmaps(id) ON DELETE CASCADE,
  tenant_id  UUID NOT NULL,
  node_id    VARCHAR(40) NOT NULL,
  link_type  VARCHAR(20) NOT NULL,
  link_id    VARCHAR(100) NOT NULL,
  PRIMARY KEY (map_id, node_id)
);

CREATE INDEX IF NOT EXISTS idx_mindmap_links_target ON mindmap_links (tenant_id, link_type, link_id);
```

### 5.3 노드 구조 (doc 내부, camelCase)

```js
{
  id: 'n-ab12cd',          // 맵 내 고유
  text: '검사 화면',
  children: [ /* Node */ ],
  side: 'right',           // 루트 1단계 자식만 (balanced 레이아웃)
  structure: null,         // 가지별 구조 override: 'logic-right' | 'org-down' | 'fishbone' …
  markers: ['priority-1', 'task-50'],
  labels: ['검토필요'],
  startDate: null,
  progress: 0,
  boundary: null,          // { title } — 이 노드의 자식 전체를 경계로 묶음
  summaries: [],           // [{ from: idx, to: idx, text }]
  numbering: false,
  collapsed: false,
  color: 'blue',           // 테마 토큰 키 — 색상값 직접 저장 X (다크/글래스 테마 대응)
```

## 6. API (`server/routes/mindmaps.js`)

| 메서드 | 경로 | 설명 |
|--------|------|------|
| GET | `/api/mindmaps?scope=&projectId=&q=` | 목록 (doc 제외, 권한 필터) |
| GET | `/api/mindmaps/:id` | 단건 (doc 포함) |
| POST | `/api/mindmaps` | 생성 (`template` 지정 시 서버에서 초안 생성) |
| PUT | `/api/mindmaps/:id` | 저장 — `version` 필수, 불일치 시 409 |
| DELETE | `/api/mindmaps/:id` | 소프트 삭제 |
| POST | `/api/mindmaps/:id/duplicate` | 복제 (내 개인 맵으로) |
| PUT | `/api/mindmaps/:id/pin` | 즐겨찾기 (version 안 올림) |
| GET | `/api/mindmaps/members` | 공유·담당자 선택용 (사용 권한 여부 포함) |
| GET · PUT | `/api/mindmaps/access/users` · `/:userId` | 사용 권한 현황 · 부여/회수 (admin) |
| POST | `/api/mindmaps/import` | `.xmind`·OPML 업로드 → 맵 생성 (Phase 2 — Markdown 은 클라이언트에서 변환) |
| POST | `/api/mindmaps/ai` | AI 기능 (3.5, Phase 2) |
| POST | `/api/mindmaps/resolve` | 참조 노드 일괄 해석 `[{type,id}]` → 상태 요약 (권한 없는 항목은 `locked`) |
| GET | `/api/mindmaps/by-link?type=&id=` | 역참조 — 이 항목이 포함된 맵 목록 |

- `resolve`는 타입별 1쿼리(`WHERE id = ANY($1)`)로 묶어 N+1 방지
- 편집 잠금은 기존 `/api/locks` 재사용 (`resourceType='mindmap'`)
- 라우트 인벤토리(`lib/route-inventory.js`)·감사 로그(`audit`) 등록

## 7. 프론트 구현 메모

- **렌더링: 자체 구현 권장** (HTML 노드 `div` 절대배치 + SVG 곡선 연결선)
  - 이유: 참조 노드 카드(배지·진척바)를 기존 CSS(`style.css`, 글래스 테마 토큰)로 그대로 꾸밀 수 있음. 외부 라이브러리(Mind-Elixir, jsMind 등)는 노드 커스텀 렌더·테마 연동에서 결국 우회 코드가 많아짐.
  - 레이아웃: 하위 트리 높이 합산 방식의 단순 tidy tree (O(n)), 접힌 노드 제외
  - 성능: 줌/팬은 컨테이너 `transform`만 변경, 노드 텍스트 편집 시 해당 노드만 재배치
- 파일: `mindmap.js`(목록·편집기), `mindmap-layout.js`(레이아웃·순수 함수 → Jest 테스트), 스타일은 `style.css`의 `.mm-*`
- `mode.js`/`setPage`에 `mindmap` 등록, `WM_TAB_DEPS`에 참조 타입 의존성 등록
- 되돌리기: doc 스냅샷 스택(최대 50), 저장과 독립
- 모바일(<768px): 아웃라인 보기 기본, 맵은 읽기 + 핀치 줌

| XMind 고급 | 여러 시트(최대 20, 탭 · 이름 바꾸기 · 삭제) · 관계선(점선 화살표 + 설명) · 경계(가지 묶음 + 제목) · 요약(하위 묶음 옆 중괄호 + 글상자) · 하위 번호(1 · 1.1) |
| 가져오기 · 내보내기 | `.xmind`(XMind 2020+ content.json · XMind 8 content.xml — 제목·노트·마커·진척·라벨·링크·접힘·경계·요약·관계선·구조) · `.opml` 가져오기, OPML 내보내기 |
| AI | 하위 주제 제안 · 가지 요약 · 글 → 가지 · WBS 초안 (편집기 ✨ AI 메뉴) + 새 맵 "글을 맵으로 정리" · "프로젝트 WBS 초안". 결과는 점선 미리보기 → [모두 채택] / [모두 버리기], 채택 전에는 저장되지 않음. 시간당 30회, `ai_query_usage` 기록, 감사 로그. 서버에 `ANTHROPIC_API_KEY` 가 없으면 메뉴가 보이지 않음 |

### 12.2 기획과 달라진 점

- **상태 갱신**: `wmDataBus` 실시간 대신 맵을 열 때 + [↻ 상태] 버튼으로 다시 불러옴 — 다른 사람이 바꾼 내용은 이벤트로 오지 않기 때문
- **원본과 맞추기**: "제안 후 확인" 대신 버튼을 누르면 바로 추가(되돌리기 가능)
- **승격**: 기존 생성 폼을 여는 대신 마인드맵 전용 간단한 창. 체크리스트 승격은 빠짐(체크리스트는 단계별 묶음이라 주제와 1:1 로 맞지 않음)
- **경계**: XMind 의 "형제 범위" 대신 한 주제와 그 하위 전체를 묶음 (가져올 때 범위는 하위 주제마다 경계로 바꿈)
- **요약**: 하위 전체에 하나 (XMind 의 일부 범위 요약은 가져올 때 하위 전체로)
